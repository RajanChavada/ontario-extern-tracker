# Ontario Extern Tracker: https://ontarioexterns.ca

A free, mobile-first page that answers one question: **which Ontario paid nursing extern postings are open now, which are talent pools, what's the closing date, and do I meet the listed criteria?** Each entry links to the hospital's own posting and shows when it was last verified.

**Status:** set up for GitHub → Cloudflare Pages (`docs/DEPLOY.md`); not deployed yet. No backend, no accounts, no payments.

## Run it
```
npm test                              # 25 tests: Ontario dates, deadlines, staleness, criteria, .ics (folding, static files, Google link), data validation
node scripts/build-ics.mjs            # regenerate cal/*.ics after ANY data change (a test fails if they're out of date)
node scripts/build-dist.mjs           # production folder dist/ for https://ontarioexterns.ca (site.json); Cloudflare runs the same
node scripts/check-data.mjs           # what each entry shows today and which need a re-check
python3 -m http.server 8731 --bind 127.0.0.1   # then open http://127.0.0.1:8731
```
**Testing on your phone (same Wi-Fi, local network only):**
- Run `python3 -m http.server 8731 --bind 0.0.0.0`.
- Open `http://<your-Mac's-LAN-IP>:8731` on the phone. Find the IP with `ipconfig getifaddr en0`.
- Stop the server (Ctrl-C) when you're done.
- **Expect the .ics download to be blocked in Chrome over the LAN address.** Chrome blocks downloads from plain-HTTP sites other than localhost ("site isn't using a secure connection"). This was reproduced in Chrome 157 for both the old and new methods. It's a property of the local preview, not of the file. On the phone, test "Google Calendar" instead, or test .ics after an HTTPS deploy. On 127.0.0.1 the .ics downloads normally.

## Files
- `index.html`, `assets/app.js`, `assets/styles.css`: the tracker UI.
- `assets/logic.js`: pure status, eligibility, date, .ics and Google Calendar link logic. Unit-tested; no AI.
- `cal/<id>.ics`: static calendar files, generated by `scripts/build-ics.mjs` (served as `text/calendar`).
- `data/hospitals.json`: the hand-maintained dataset (`dataset_checked` is the last full check). See `REFRESH.md`.
- `what-is-a-clinical-extern-ontario.html`: the one SEO page (extern vs placement vs NGG), with official sources.
- `assets/analytics.js`, `assets/config.js`: the Umami integration. It stays **off** while `UMAMI_WEBSITE_ID` is blank.
- `docs/DESIGN.md`: references, tokens and the design rules for this version.
- `docs/DEPLOY.md`: Cloudflare Pages, Umami, Search Console steps and the post-deploy checklist.
- `marketing/`: carousel template, fact-gated renderer and post sources (`marketing/CAROUSEL.md`). Rendered images and screenshots are generated locally and not committed.
- Outreach drafts, organization contacts, the feedback log and scorecards are kept outside this repository.

## Rules the code enforces
- **"Open"** only with an https link to an actual posting that was reachable and verified in the last 7 days. Otherwise the entry shows **Unconfirmed**.
- **Vacancy vs talent pool vs "posting live, type not stated"** are separate status labels. A "typical window" is never shown as an upcoming opening.
- **Eligibility wording:** "Meets listed criteria" / "Check with employer" / "Doesn't meet listed criteria". It never says "eligible".
- **Dates:** closing dates are calendar dates in America/Toronto, with no time of day. "Add to calendar" offers an .ics file (all-day event, 3-day reminder) or a Google Calendar link (all-day). Neither has a time.
- **Privacy:** filters run in the browser and selections are never sent or stored (localStorage holds only the last visit date). Analytics events carry only which control was used, plus hospital and status on clicks.
